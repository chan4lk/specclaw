# T2 report

`specclaw-azdo-issue` gains three subcommands:
- **`optin <dir> <change> <tag> <upn>`:** reuses the rev-guarded `tag_update` core in a new `optin` mode. One PATCH tests `/rev`, replaces `System.Tags` with the tag added, and adds `System.AssignedTo` = upn when the item is unassigned.
  - An item assigned to someone else exits 4 and makes no write.
  - An item already assigned to the caller and already tagged is a no-op.
  - A 4xx after the revision moved retries, as the tag core already does.
- **`whoami`:** reads `connectionData` and prints `{upn, name, id}` for the identity behind `AZDO_TOKEN`.
- **`records`:** reads the work-item comments (newest first, html or `<br>` bodies) and parses each "specclaw-fleet run update" into key/value pairs plus `at`.

**Tests:** the new suite `run-azdo-issue-optin-tests.sh` is registered in CI. The existing claim, history and fields suites still pass.
