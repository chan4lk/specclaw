# T1 report

**What T1 adds:**
- **`lib/settings.sh`:** `load_fleet_settings` runs once in the router, before any subcommand. It reads the `fleet:` block of `$SPECCLAW_DIR/config.yaml` and exports `FLEET_<KEY>` (or `KUBECONFIG`) only when that variable is unset.
- **Precedence:** flag, then env (even when set but empty), then config, then default.
- **Parsing:** quotes, inline comments and CRLF are handled. An unknown key gets a warning.
- **Secrets:** a value that looks like a secret (`sk-`, a JWT, or a run of 52 or more base64 characters that is not an `@sha256:` digest) makes the command die, naming the key and never the value.
- **Pipelines:** both templates drop the six per-setting variables and their env entries. The dispatch script runs `export FLEET_KUBE_CONTEXT=`, so the hosted run always uses the kubeconfig that the Kubernetes task logged in.

**Tests:**
- `ac22_settings.sh` covers precedence, parsing, the secret refusal, a flag beating config, and the pipeline clearing the context.
- `ac15` now asserts the templates' variable sets.
