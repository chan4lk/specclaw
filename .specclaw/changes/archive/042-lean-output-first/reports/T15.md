# T15 — Extract `specclaw-quality-scan`

- Moved, not copied: the collector's JSON helper, config reader, capability table, thresholds, scan exclusions, tool probe, file enumeration and the scc/lizard/jscpd runners now live in `plugins/specclaw/lib/quality-scan.sh` (1,083 lines). `specclaw-bf-quality-collect` sources it (3,333 → 2,267 lines) and keeps its module join, clone identity, QI registry and rendering.
- This differs from design decision 10: the collector sources a shared lib instead of calling the new script. That keeps the collector's output byte-identical, which the 23i comparison against origin/main checks.
- `bin/specclaw-quality-scan [<root>] [--gate]`: same enumeration (plus untracked, not-ignored files) and exclusions; tools from PATH, else `uvx lizard` / `npx --yes jscpd`. Prints `tools`, `thresholds`, `totals`, `duplicates[]` (both locations), `functions[]` (over warn, levelled warn/high) and `gate`. Exit 1 when the gate fails, 2 when a tool did not run.
- Fixed a latent bug in the shared jscpd runner. With real jscpd 5.4.1 and `--no-gitignore`, `.git/hooks` samples took over the `--summary-top` slots, so every real file dropped out and the result was a parse_error. `.git` is now always ignored. Confirmed with real jscpd 5.4.1 and lizard: a planted 23-line duplicate is reported, and the gate fails at 100% duplication.
- shellcheck gate: only files with a sh/bash shebang are linted, since `bin/` now has a Python helper. Added targeted disables for the runtime-resolved `source` and the shims. No new findings.
- AC-13: `run-quality-tests.sh` shows the same 9 failures as the pre-change baseline (all macOS-only, no `timeout`), with 327 passing. `run-bf-e2e-run-tests.sh` and `run-narration-gate-tests.sh` pass.
