# T14 — `specclaw-preset-check`, init detection, build/verify wiring

- `bin/specclaw-preset-check` (Python 3): checks git-tracked plus untracked-not-ignored code files (py, ts, tsx, js, jsx, mjs, cjs, cs) for `max_lines` (default 80, `preset_overrides.max_lines`, block or inline map), whole-line comments (pragma allow-list: eslint-disable, @ts-, prettier-ignore, type: ignore, noqa, pyright:, triple-slash reference, shebang), and .csproj `ProjectReference` direction (Domain < Application < Infrastructure < Api). Applies `lib/quality-exclusions.yaml` plus the project's `quality.exclusions`, except the `tests` category. JSON out; exit 0/1/2. Trailing comments after code are not detected (documented limitation).
- `lib/quality-exclusions.yaml` moved from specclaw-bf back to core: core owns the quality policy now. The bf collector finds it through the core `bin/` on PATH. `run-quality-tests.sh` 23i (which runs the pre-change collector from origin/main) stages a temporary copy beside it.
- `specclaw-init` detects presets: `package.json` with `next` → nextjs; `react` + `vite` → react-spa; other package.json → node; `*.csproj`/`*.sln` (depth 3) → dotnet; `pyproject.toml`/`requirements.txt` → python. Writes `presets: [..]` and prints the list; the init skill asks the user to confirm.
- Build/verify wiring is in the T16 commit (same files).
- Smoke run: a Next.js + .NET dir gives `presets: [nextjs, dotnet]`; an empty dir gives `presets: []`.
