# Spec: Keep Azure DevOps PR descriptions under the 4,000-character limit

**Change:** 041-azdo-pr-description-limit
**Size:** bounded
**Created:** 2026-09-27

## Problem

`build_pr_description()` in `plugins/specclaw/bin/specclaw-azdo-pr` caps each section by lines, never by characters. The assembled description routinely exceeds Azure DevOps' 4,000-character `description` limit, and `POST .../pullrequests` rejects the PR after every gate has passed.

## Functional Requirements

- **FR1** — The description sent to ADO is at most `max` characters, where `max` = `azdo.pr_description_max` from `config.yaml` if it is a positive integer, else `3900`; a configured value below 1000 is raised to 1000 with a warning (below that the hard cap would eat the verdict line).
- **FR2** — When the untruncated description is ≤ `max`, it is emitted byte-identical to today's output.
- **FR3** — When over budget, sections are shrunk lowest-value first: Time accounting → Staged files → Verification excerpt → Tests → Acceptance Criteria → Summary. Each shrink stops as soon as the whole fits.
- **FR4** — A shrunk section is cut at a line boundary and ends with `_…truncated — full text in \`.specclaw/changes/<change>/<file>\`_`. If even heading + pointer does not fit, the section body becomes the pointer line alone.
- **FR5** — The `**Verdict:** …` line and the `🤖 Generated by SpecClaw` footer are never removed.
- **FR6** — A final hard cap guarantees FR1 even if FR3/FR4 still overshoot (e.g. one enormous line); a `WARNING:` naming the truncated sections is printed to stderr whenever any truncation happens (and a second one when the hard cap fires).
- **FR7** — Length is measured in characters (`${#var}` under a UTF-8 locale); under a byte locale it over-counts (safe), and every cut lands on a newline so a multi-byte character is never split.

## Non-Functional Requirements

- Bash + coreutils only; no new dependency. `shellcheck-gate.sh` passes with the baseline unchanged.
- Config key is 2-level (`azdo.pr_description_max`) because this script's `yaml_val` only resolves 2-level keys. (Deviation from the proposal's `azdo.pr.description_max`, noted here deliberately.)

## Acceptance Criteria

- **AC1** — Given fixture artifacts whose untruncated description is > 8,000 characters, the output is ≤ 3,900 characters.
- **AC2** — In AC1's output the verdict line and footer are present, and at least one truncation pointer naming a real change-dir file is present.
- **AC3** — Given small fixture artifacts, output equals the pre-change output byte-for-byte (golden captured from the current function).
- **AC4** — With `azdo.pr_description_max: 1500` in config, output is ≤ 1,500 characters.
- **AC5** — A single 10,000-character line in the proposal still yields output ≤ budget and a stderr `WARNING:`.
- **AC6** — Time accounting is shrunk/dropped before Summary is touched (Summary intact when shrinking lower sections suffices).
- **AC7** — The new suite is registered in `.github/workflows/ci.yml`; shellcheck gate passes.
- **AC8** — Patch version bumped in sync across `plugins/specclaw/.claude-plugin/plugin.json`, `plugins/specclaw/.codex-plugin/plugin.json`, `.claude-plugin/marketplace.json`.

## Edge Cases

- Non-numeric / zero / missing `azdo.pr_description_max` → default 3900.
- Missing optional artifacts (no staged-files report, no timeline) → those sections are absent, as today.
- Multi-byte content (emoji, non-ASCII) — counted as characters.

## Approach

Refactor `build_pr_description()` to build each section into its own variable, then pass them to a new `fit_description` helper that assembles, measures, and shrinks sections in the FR3 order before a final hard cap. The fixed skeleton (headings, verdict line, footer) is kept outside the shrinkable bodies so FR5 holds structurally. The test extracts the functions from the script with awk (pattern used by `run-narration-gate-tests.sh`) and runs them against fixture change dirs, so no network, auth, or production-only flag is needed.

File map:
- `plugins/specclaw/bin/specclaw-azdo-pr` — budget read, `fit_description`, section refactor
- `plugins/specclaw/templates/config.yaml` — commented `pr_description_max` under `azdo:`
- `plugins/specclaw/tests/run-azdo-pr-description-tests.sh` — new suite (+ golden fixture)
- `.github/workflows/ci.yml` — register suite
- version files (3) listed in AC8
