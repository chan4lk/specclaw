# T3 report

`specclaw-fleet optin <change>... [--dry-run]` (`lib/optin.sh`):
- It reads the caller from `specclaw-azdo-issue whoami`, which is the `AZDO_TOKEN` identity. If that fails, it stops before any write.
- For each change, it calls `specclaw-azdo-issue optin … fleet:auto <caller>`: one rev-guarded PATCH that assigns the item when it is unassigned and adds the tag.
- An item assigned to someone else exits 4. The other changes in the same call still proceed.
- A missing work item exits 1 with "run: specclaw-fleet trigger <c> --create".
- `--dry-run` prints the plan per change (assign and tag, tag only, already opted in, or refused with the other assignee's name) and writes nothing.
- The exit status is the worst per-change code.

**Tests:** `ac23_optin.sh` covers self-only assignment, a mixed list, the dry run, no work item, and no identity.
