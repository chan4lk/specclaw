# T4 report

`specclaw-fleet status [<change>...] [--json] [--watch [N]] [--since ISO]` (`lib/status.sh`, `lib/status-render.sh`) is read-only.
- **Header:** the latest run of `fleet.pipeline`, read over AzDO REST with the PAT (the new `azdo_rest` in `common.sh`).
- **Rows:** one per change. Each row shows:
  - the work item;
  - its state;
  - the assignee;
  - which fleet tags it has;
  - the newest fleet record after `--since`, or `waiting`, or `not-opted-in` when the item lacks `fleet:auto`;
  - the newest Job labelled with the change, with its phase and pod phase (`kc`, so `FLEET_KUBE_CONTEXT` is honoured).
- **Defaults:** with no arguments, every approved change is listed. `--json` emits `{pipeline, changes}`.
- **`--watch N`:** re-renders until every row is terminal (`pr_open`, `failed`, `not-opted-in`, or no work item). It defaults `--since` to the moment the watch started.
- **Unreadable sources:** an unreadable AzDO or cluster shows `?` and is never terminal.

**Tests:** `ac24_status.sh` covers the fields, `--since`, unreadable sources, the watch exit, and no write calls.
