# T4 report

- **`feature init <m>`:** validates the graph and writes `.specclaw/features/<m>/` (proposal with the waves, status, and an approved `state.json` with `kind: feature`), then creates the work item through the features fallback. An empty feature is refused.
- **`feature start <m>`:** requires the record on the pushed ref. It creates `feature/<m>` from the pushed `fleet.ref` only when the branch is missing, then queues the pipeline on `feature/<m>`.
- **`feature advance <m>`:** idempotent.
  - Dispatches each `ready` member on `feature/<m>` through the normal gates.
  - A `conflict` member is re-dispatched once with `--force` and `FLEET_MERGE_REF`, then tagged `fleet:conflict-retried`. A second conflict records `failed exit=merge-conflict` and tags `fleet:refused`.
  - `failed` members block only their dependents.
  - When every member is merged, it dispatches the feature item in `integrate` mode, targeting `FLEET_TRUSTED_BRANCH` (default `main`).
  - Dispatch exits 3, 4 and 5 are not errors; anything else counts as an error and fails the run.
