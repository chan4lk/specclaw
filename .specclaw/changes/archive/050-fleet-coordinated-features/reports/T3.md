# T3 report

`lib/feature-state.sh` derives each member's base state. The first rule that matches wins:
1. **merged:** the PR from the newest fleet record is completed into `refs/heads/feature/<m>` (read through `azdo_rest git/pullrequests/<id>`), whatever the merge type. If there is no such PR, the change branch being an ancestor of `origin/feature/<m>` also counts as merged.
2. **conflict:** the PR is active with `mergeStatus` `conflicts`.
3. **pr_open:** the PR is active.
4. **failed:** the item is tagged `fleet:refused`, or the last record is `failed`.
5. **running:** the last record is `dispatched` or `running`.
6. **not-opted-in** or **pending:** from the consent check.
7. **`?`:** the item could not be read.

`feature_states` then turns `pending` into `ready` when every dependency is merged, and into `waiting` otherwise. `feature plan` shows each member's wave, state and dependencies.

**Tests:** `ac29_feature_state.sh`, a table that walks through every state.
