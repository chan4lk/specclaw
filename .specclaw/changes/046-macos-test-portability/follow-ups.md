- [minor B3] `plugins/specclaw/bin/specclaw-run-long:197` Appending `| tr -d ' '` makes `tr` the pipeline's exit status, so `|| echo 0` can no longer fire when `wc` fails. The fallback is dead code and a failed count comes back as an empty string instead of 0. Same at the `total=` line near 332. Capture `wc` output first and strip the padding with parameter expansion, e.g. `n=$(wc -l < f 2>/dev/null) || n=0; n=${n//[[:space:]]/}`. This only matters if the script does not use `pipefail`, which the diff does not show. (round 1) <!-- fp:44a9efba5c29 -->

- [minor B3] `plugins/specclaw/bin/specclaw-run-long:332` Piping into `tr -d ' '` makes the `|| echo 0` fallback dead unless pipefail is set, because the pipeline's status is tr's.
